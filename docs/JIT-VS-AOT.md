# JIT and Native AOT comparison

The CLI targets .NET 10 and uses the same code for all variants. `benchmarks/publish.ps1` publishes `win-x64` Release builds to separate directories: framework-dependent JIT, self-contained JIT and Native AOT. ReadyToRun and single-file publishing are disabled. Native AOT requires the .NET Native AOT prerequisites, including the Windows C++ toolchain.

From PowerShell, run `./benchmarks/publish.ps1 -OutputRoot <directory>`, then `./benchmarks/smoke.ps1 -PublishRoot <directory>`. The latter requires all three builds and checks a basic scan, repeated cache use, help, error exit and matching totals. It is not a substitute for the complete test suite.

Prepare fixtures with `./benchmarks/prepare-fixtures.ps1 -OutputDirectory <new-fixtures-directory>`. Run `./benchmarks/measure.ps1 -PublishRoot <publish-directory> -FixtureRoot <new-fixtures-directory> -OutputDirectory <new-results-directory>`. All three paths should be outside the repository; output directories must not already exist. The script records raw JSON/CSV observations, medians and ranges; it retains independent fixture copies in the results directory. Review the recorded Git status and comparison summaries. The scripts have not yet been validated end-to-end with Native AOT in this environment, so do not treat their output as published experimental results without independently validating the setup. Publication timing and size are recorded separately by the publish script. The help scenario measures process invocation and help completion, not a separately observable startup boundary. Stopwatch measures elapsed time, not CPU time; peak-memory sampling can miss short peaks. A new process is not an OS cold start when the filesystem cache is uncontrolled. Record Defender and background load rather than assuming they have no influence.

## Expanded experiment

Generate three deterministic sets with `prepare-fixtures.ps1 -OutputDirectory <new-directory> -Seed 12345 -AverageFileBytes 1024`; the sets contain 20, 500 and 5,000 source files. The manifest records seed, requested average size, source bytes and expected counts. Choose another average size to change the amount of data per file. Do not scan the original fixture directories: measurement requires them without `.cline` state.

`measure.ps1` accepts `-Warmups`, `-Iterations`, `-Series`, and `-Order Rotating` (default) or `Grouped`. Rotation is deterministic; each raw result includes its sequence number and series. The script checks expected totals and cache reuse, then compares aggregate scan summaries across variants. It records median, minimum, maximum and nearest-rank P90/P95 without removing outliers. The check compares totals, not all per-file statistics. Copies and cache preparation happen before each timed process. Repeated scenarios prepare state using that variant. The process output capture and invocation overhead remain part of elapsed time.

Peak Working Set and Private Bytes are not measured: `peakMemoryBytes` is null. Polling short-lived processes could miss peaks; use an independently validated process-lifetime observer before drawing memory conclusions. The file-count/byte manifest is not a cryptographic identity check. Scripts and Native AOT must be validated end-to-end on the target host. The revised fixtures and order are not directly comparable to the earlier experiment.
